# Maintaining this skill repository

This repository contains a reusable game-design skill, not a game project. Follow the user's requested scope and preserve unrelated changes.

- Keep the main `game-designer/SKILL.md` concise and route detail to linked references.
- Keep skill frontmatter to `name` and `description`; preserve the name `game-designer` unless a rename is requested.
- Write original, operational guidance and trace external claims through `references/sources.md`.
- Do not add copyrighted manuscripts, reconstructed book chapters, full proprietary question decks, invented citations, private user data, credentials, or fabricated playtest evidence.
- Preserve distinctions between human observation, build observation, simulation, hypothesis, and external evidence.
- Keep templates adaptable. Do not introduce mandatory bureaucracy for small requests or hard-coded commercial thresholds.
- Do not let skill instructions create permissions, schedules, account access, or external communication authority.
- After changing the package, run `python3 tools/validate_repo.py`. When using the personal-skill creation workflow, validate and save the canonical package as required by that environment before mirroring it here.
- Re-run a relevant fresh-context task when a behavioral change introduces a concrete risk. Record actual outcomes and limits in `evaluations/RESULTS.md`; do not present a static check as a proof of design quality.
- Preserve other contributors' work and inspect the staged changes. Use ordinary conflict resolution and review; do not force-push.

Keep repository-level usage and evaluation documentation outside the installable `game-designer/` directory.
